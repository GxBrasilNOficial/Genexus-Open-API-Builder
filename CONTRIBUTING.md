# CONTRIBUTING.md

# Contribuindo com o Genexus Open API Builder

Obrigado pelo interesse em contribuir.

Este projeto nasce open source para gerar valor real à comunidade GeneXus.

Toda ajuda útil é bem-vinda.

---

# Formas de Contribuir

Você pode ajudar com:

- reportar bugs
- sugerir melhorias
- melhorar documentação
- testar versões
- enviar Pull Requests
- compartilhar feedback real de uso
- propor exemplos práticos

---

# Antes de Contribuir

Recomendado:

1. Ler README.md  
2. Entender objetivo atual do projeto  
3. Ver issues abertas  
4. Validar se já existe discussão semelhante

---

# Reportando Bugs

Ao abrir issue, tente incluir:

- versão usada
- ambiente
- passos para reproduzir
- comportamento esperado
- comportamento atual
- prints/logs se possível

Prefira o formulário **Bug ou problema de uso** em New issue.

---

# Feedback fora do GitHub (mantenedor)

Quando o relato chegar por grupo, mensagem direta ou outro canal fora do GitHub:

1. Abra a issue no lugar da pessoa.
2. Cole o texto original em bloco de citação, sem reescrever.
3. Registre canal e data de origem; nome ou handle só se a pessoa autorizar.
4. Aplique o label `feedback-externo` (e `instalacao` / `alpha-0.1.0` quando couber).

---

# Sugerindo Funcionalidades

Explique:

- problema real resolvido
- quem precisa disso
- ganho esperado
- alternativa atual
- impacto percebido

Melhor que apenas:

"seria legal ter..."

Prefira o formulário **Sugestão** em New issue.

Para pergunta rápida ou relato curto sem os campos do bug, use **Dúvida / outro**.

---

# Pull Requests

Preferimos PRs:

- pequenos
- focados
- claros
- testáveis
- alinhados ao propósito do projeto

---

# Padrão Esperado

- código legível
- nomes claros
- baixo acoplamento
- sem complexidade desnecessária
- sem quebrar fluxo principal

---

# Processo Sugerido

Issue  
→ conversa curta  
→ implementação  
→ Pull Request  
→ revisão  
→ merge ou ajustes

---

# O Que Evitar

- PR gigante sem contexto
- reescrever tudo sem motivo
- features fora do foco atual
- discussões hostis
- mudanças quebrando compatibilidade sem aviso

---

# Filosofia do Projeto

Valorizamos:

- utilidade real
- simplicidade
- transparência
- colaboração
- melhoria contínua

---

# Código de Conduta Resumido

Trate todos com respeito.

Discordâncias técnicas são normais.  
Ataques pessoais não.

---

# Dúvidas

Use Issues (formulário **Dúvida / outro** para mensagem curta) ou Discussions quando disponíveis.

---

# Obrigado

Projetos open source crescem com colaboração séria.

Sua contribuição importa.
