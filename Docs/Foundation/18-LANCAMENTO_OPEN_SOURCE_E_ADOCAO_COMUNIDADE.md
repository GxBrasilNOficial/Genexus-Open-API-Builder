No início, priorizar utilidade real e confiança pública.

---

# 6. FASE 1 — Publicação Inicial

## Entregas mínimas

- repositório público organizado
- README forte
- licença open source definida
- screenshots ou GIF real
- instruções de instalação
- roadmap resumido
- issues habilitadas

## Objetivo

Primeira impressão excelente.

[ADP-F18]

---

# 7. README Oficial Deve Responder

- o que resolve?
- para quem serve?
- como instalar?
- como usar?
- status atual?
- como contribuir?

## Regra

Visitante deve entender em poucos minutos.

[OSS-F18]

# 11. Estrutura de Feedback

## Coletar

- bug report
- sugestão
- dificuldade instalação
- feature pedida

## Ferramentas

- Discussions

# 12. O Que NÃO Fazer no Lançamento

Evitar:

- anunciar cedo demais sem README
- prometer recursos futuros demais
- esconder limitações
- abandonar issues abertas
- marketing exagerado
- roadmap fantasioso

[OSS-F18]
