# B087 — Posse do API Object na metadata

## Objetivo

Separar a `Description` pública do API Object (copiada para `info.description` no OpenAPI) da sentinela de posse. Depois desta frente, a posse consulta o File de metadata (`ownership.apiName` / `ownership.apiGuid` + integridade B067). A `Description` só permanece como fallback quando o File ainda não existe.

## Comportamento

| Situação | Resultado |
|---|---|
| File de metadata próprio presente, `ownership` casa com o API Object, integridade B067 ok, Service Source gerenciado | Próprio — **mesmo se a Description tiver sido editada** |
| File de metadata próprio presente, mas integridade ou ownership divergem | Não próprio (não cai no fallback da Description) |
| File de metadata ausente e Description igual à frase gerada padrão (com ou sem ponto final legado) | Próprio (fallback de transição) |
| File ausente e Description editada | Não próprio |

Na criação, a Description inicial é `REST API for <Transaction>, generated by Genexus Open API Builder` (**sem** ponto terminal; Description de objeto GeneXus costuma ser assim). A forma legada com ponto final continua aceita no fallback e na integridade B067. No reencontro, a Description **não** é sobrescrita.
