**Date:** 2026-08-24

**Workstream:** `B102` — forward Business Component error messages in HTTP 422

**Tag:** `v0.1.0-alpha.4`
**Release:** [Alpha on GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.4)

**Languages:** [Português do Brasil](0.1.0-alpha.4.md) · [Español](0.1.0-alpha.4.es.md) · [English](0.1.0-alpha.4.en.md)

This release replaces the Alpha's fixed rejection sentence with the actual Business Component rule text in the HTTP 422 body.

## Behavior change

This is not a changelog bullet. If you already consume a generated API, read this first.

- On a business-rule rejection, `Create` and `Update` respond with **HTTP 422** and `ErrorResponse.Code = validation_error`.
- `ErrorResponse.Message` now carries `Error()` rule text, joined with `" | "` when there is more than one message, visibly truncated at 2048 characters with a trailing `...`.
- The body gains the `Messages[]` collection, typed by `sdt_API_ErrorMessage`. In each item, `Code` keeps the Business Component message identifier when one exists; otherwise it uses `business_rule`. Only **error** messages are forwarded; `Msg()` is excluded.
- The published YAML declares `Messages` as `type: array`. The native generator does **not** emit `maxLength` for `LongVarChar`.
- Forwarding is **on by default**. You can turn it off per knowledge base (preferences) and per API (Wizard, Security tab). When off, the body returns to the generic `"Business rules rejected the request."`.
- An already generated API **does not change by itself**, but the reach differs between the two halves of the contract. The Source — what fills `Message` and `Messages[]` at runtime — changes only when you reopen the Wizard on that API. The shared `sdt_API_ErrorResponse` SDT is unique per knowledge base: regenerating **any** API rewrites it, and the error schema published in the other APIs' YAML starts declaring `Messages[]` on the next Build, without those APIs being reopened.
- Callers that compared the Alpha's fixed string to detect a rule rejection now receive the real Business Component text. Decide by `Code`, not by message text.

Generation still covers only the Transaction's first level; sublevels are silently ignored. That limitation was already stated in the three `README` files and in `DEMO` before this cut.

## You must choose the correct DLL

Download and install only the file that matches your IDE version:

| GitHub Release asset | For | Not for |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15, and later U14+ releases | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

The `-gx18u13` suffix exists to distinguish the public download. Do not rename a DLL to make it look like another line, and do not install both DLLs in the same IDE.

## What is included

- Forwarding of Business Component error messages in `Message` (`LongVarChar`) and `Messages[]`.
- Per-KB default and per-API choice, outside the B067 hash.
- Conservative re-encounter of the Alpha fixed-text block.
- Wizard checkbox: *Include Business Component error messages in the HTTP 422 body*.

## Validation

- Live HTTP on `.NET`/PostgreSQL and `.NET Framework`/SQL Server (`apiTeste`): rule text, UTF-8 accents, visible truncation, `Messages[]`, opt-out, and exclusion of `Msg()`.
- U13: satellite Release build with the asset checker.
- U15: canonical Release build with the same checker.

## Installation

Follow the [public installation guide](../Public/INSTALL.md). In brief:

1. choose the DLL using the table above;
2. with the GeneXus IDE open, use **Extensions Manager → Add > Local**;
3. close the IDE completely;
4. run `genexus /install` in the corresponding installation;
5. reopen the IDE and verify the Genexus Open API Builder menus.

The GitHub Packages `.nupkg` is not the IDE installer. For public installation, use the Release DLL asset.

## Known limitations

- Generation covers only the Transaction's first level; sublevels are silently ignored.
- The `DELETE` service is not part of the MVP.
- GeneXus native OpenAPI YAML retains the limitations documented in [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md), including the absence of `maxLength`.
- On IIS + .NET Framework, the `PUT` verb requires the handler adjustment described in the [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- Installation without elevation and updates performed only through Add > Local over an already installed DLL remain unproven.
- This is still an Alpha, not a Beta; Sprint 9 and known limitations remain explicit.
