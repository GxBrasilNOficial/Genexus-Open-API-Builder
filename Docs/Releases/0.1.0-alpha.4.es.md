# Release 0.1.0-alpha.4

**Fecha:** 2026-08-24

**Frente:** `B102` — reenvío de los mensajes de error del Business Component en HTTP 422

**Tag:** `v0.1.0-alpha.4`
**Release:** [Alpha en GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.4)

**Idiomas:** [Português do Brasil](0.1.0-alpha.4.md) · [Español](0.1.0-alpha.4.es.md) · [English](0.1.0-alpha.4.en.md)

Esta versión entrega el texto real de las rules del Business Component en el cuerpo HTTP 422, en lugar de la frase fija de la Alpha.

## Cambio de comportamiento

No es un ítem de la lista de mejoras: quien ya consume una API generada necesita saber esto.

- Si una regla rechaza la operación, `Create` y `Update` responden **HTTP 422** con `ErrorResponse.Code = validation_error`.
- `ErrorResponse.Message` pasa a cargar el texto de las rules `Error()`, concatenado con `" | "` cuando hay más de una, truncado visiblemente en 2048 caracteres con `...` al final.
- Entra el miembro colección `Messages[]`, tipado por `sdt_API_ErrorMessage`. En cada ítem, `Code` conserva el identificador del mensaje del BC cuando existe; sin identificador, usa `business_rule`. Solo entran mensajes de **error**; `Msg()` queda fuera.
- El YAML publicado declara `Messages` como `type: array`. El generador nativo **no** emite `maxLength` para el `LongVarChar`.
- El reenvío viene **activado por defecto**. Se puede desactivar por KB (preferencias) y por API (Wizard, pestaña Seguridad). Desactivado, el cuerpo vuelve al texto genérico `"Business rules rejected the request."`.
- Una API ya generada **no cambia sola**. El contrato nuevo solo entra al reabrir el Wizard sobre esa API.
- Quien comparaba la cadena fija de la Alpha para detectar un rechazo de regla pasa a recibir el texto real del Business Component. Decida por el `Code`, no por el texto.

La generación sigue cubriendo solo el primer nivel de la Transaction; los subniveles se ignoran sin aviso. Esa limitación ya estaba en los tres `README` y en el `DEMO` antes de este corte.

## Elija obligatoriamente la DLL correcta

Descargue e instale solamente el archivo correspondiente a la versión de su IDE:

| Asset en GitHub Release | Sirve para | No sirve para |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15 y posteriores U14+ | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

El sufijo `-gx18u13` existe para distinguir la descarga pública. No cambie el nombre de una DLL para hacerla pasar por otra línea y no instale las dos en el mismo IDE.

## Qué incluye

- Reenvío de los mensajes de error del Business Component en `Message` (`LongVarChar`) y `Messages[]`.
- Preferencia por KB y elección por API, fuera del hash B067.
- Reencuentro conservador del bloque Alpha de texto fijo.
- Casilla en el Wizard: *Incluir mensajes de error del Business Component en el cuerpo HTTP 422*.

## Validaciones

- HTTP real en los environments `.NET`/PostgreSQL y `.NET Framework`/SQL Server (`apiTeste`): texto de la rule, acento UTF-8, truncamiento visible, `Messages[]`, opción desactivada, exclusión de `Msg()`.
- U13: build satélite Release con el checker de asset.
- U15: build canónica Release con el mismo checker.

## Instalación

Siga la [guía pública de instalación](../Public/INSTALL.md). En resumen:

1. elija la DLL según la tabla anterior;
2. con la IDE GeneXus abierta, use **Extensions Manager → Add > Local**;
3. cierre completamente la IDE;
4. ejecute `genexus /install` en la instalación correspondiente;
5. vuelva a abrir la IDE y confirme los menús de Genexus Open API Builder.

El `.nupkg` de GitHub Packages no es el instalador de la IDE. Para la instalación pública, use el asset DLL del Release.

## Limitaciones conocidas

- La generación cubre solo el primer nivel de la Transaction; los subniveles se ignoran sin aviso.
- El servicio `DELETE` no forma parte del MVP.
- El YAML OpenAPI nativo de GeneXus mantiene las limitaciones documentadas en [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md), incluida la ausencia de `maxLength`.
- En IIS + .NET Framework, el verbo `PUT` requiere el ajuste del handler descrito en el [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- La instalación sin elevación y la actualización solamente por Add > Local sobre una DLL ya instalada continúan sin comprobación.
- Esta versión sigue siendo Alpha, no Beta; permanecen explícitos la Sprint 9 y las limitaciones conocidas.
