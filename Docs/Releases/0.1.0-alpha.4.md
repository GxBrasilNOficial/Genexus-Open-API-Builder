# Release 0.1.0-alpha.4

**Data:** 2026-08-24

**Frente:** `B102` — repasse das mensagens de erro do Business Component no HTTP 422

**Tag:** `v0.1.0-alpha.4`
**Release:** [Alpha no GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.4)

**Idiomas:** [Português do Brasil](0.1.0-alpha.4.md) · [Español](0.1.0-alpha.4.es.md) · [English](0.1.0-alpha.4.en.md)

Esta versão entrega o texto real das rules do Business Component no corpo HTTP 422, no lugar da frase fixa da Alpha.

## Mudança de comportamento

Não é um item da lista de melhorias: quem já consome uma API gerada precisa saber disto.

- Em recusa de regra, `Create` e `Update` respondem **HTTP 422** com `ErrorResponse.Code = validation_error`.
- `ErrorResponse.Message` passa a carregar o texto das rules `Error()`, concatenado por `" | "` quando há mais de uma, truncado visivelmente em 2048 caracteres com `...` no fim.
- Entra o membro coleção `Messages[]`, tipado por `sdt_API_ErrorMessage`. Em cada item, `Code` preserva o identificador da mensagem do BC quando existir; sem identificador, usa `business_rule`. Só mensagens de **erro** entram; `Msg()` fica de fora.
- O YAML publicado declara `Messages` como `type: array`. O gerador nativo **não** emite `maxLength` para o `LongVarChar`.
- O repasse vem **ligado por padrão**. Dá para desligar por KB (preferências) e por API (Wizard, aba Segurança). Desligado, o corpo volta ao texto genérico `"Business rules rejected the request."`.
- API já gerada **não muda sozinha**, mas o alcance não é o mesmo nas duas metades do contrato. O Source — quem preenche `Message` e `Messages[]` em runtime — só muda ao reabrir o Wizard sobre aquela API. O SDT compartilhado `sdt_API_ErrorResponse` é único na KB: regerar **qualquer** API o reescreve, e o schema de erro publicado no YAML das demais passa a declarar `Messages[]` no Build seguinte, sem que elas tenham sido reabertas.
- Quem comparava a string fixa da Alpha para detectar recusa de regra passa a receber o texto real do Business Component. Decida pelo `Code`, não pelo texto.

A geração continua cobrindo apenas o primeiro nível da Transaction; subníveis são ignorados sem aviso. Isso já estava nos três `README` e no `DEMO` antes deste corte.

## Escolha obrigatória da DLL

Baixe e instale somente o arquivo correspondente à versão da sua IDE:

| Asset no GitHub Release | Serve para | Não serve para |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15 e posteriores U14+ | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

O sufixo `-gx18u13` existe para distinguir o download público. Não renomeie uma DLL para fazê-la passar por outra linha e não instale as duas na mesma IDE.

## O que entra

- Repasse das mensagens de erro do Business Component em `Message` (`LongVarChar`) e `Messages[]`.
- Preferência por KB e escolha por API, fora do hash B067.
- Reencontro conservador do bloco Alpha de texto fixo.
- Checkbox no Wizard: *Incluir mensagens de erro do Business Component no corpo HTTP 422*.

## Validações

- HTTP real nos environments `.NET`/PostgreSQL e `.NET Framework`/SQL Server (`apiTeste`): texto da rule, acento UTF-8, truncamento visível, `Messages[]`, opção desligada, exclusão de `Msg()`.
- U13: build satélite Release com inventário/checker de asset.
- U15: build canônica Release com o mesmo checker.

## Instalação

Siga o [guia público de instalação](../Public/INSTALL.md). Em resumo:

1. escolha a DLL pela tabela acima;
2. na IDE GeneXus aberta, use **Extensions Manager → Add > Local**;
3. feche completamente a IDE;
4. execute `genexus /install` na instalação correspondente;
5. reabra a IDE e confira os menus do Genexus Open API Builder.

O `.nupkg` do GitHub Packages não é o instalador da IDE. Para a instalação pública, use o asset DLL do Release.

## Limitações conhecidas

- A geração cobre apenas o primeiro nível da Transaction; subníveis são ignorados sem aviso.
- Serviço `DELETE` não faz parte do MVP.
- O YAML OpenAPI nativo do GeneXus mantém as limitações documentadas em [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md), inclusive a ausência de `maxLength`.
- Em IIS + .NET Framework, o verbo `PUT` exige o ajuste do handler descrito no [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- Instalação sem elevação alguma e atualização somente por Add > Local sobre DLL já instalada continuam sem comprovação.
- A Alpha ainda não é a Beta; a Sprint 9 e as limitações conhecidas permanecem explícitas.
