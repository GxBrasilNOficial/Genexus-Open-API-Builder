**Date:** 2026-08-30

**Workstream:** Sprint 9 — Transactions with sublevels (Phases 0–7)

**Tag:** `v0.1.0-alpha.5`
**Release:** [Alpha on GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.5)

**Languages:** [Português do Brasil](0.1.0-alpha.5.md) · [Español](0.1.0-alpha.5.es.md) · [English](0.1.0-alpha.5.en.md)

This release generates the header plus selected lines of Transactions with sublevels, with V2 metadata, Sync, and Remove covering the hierarchy.

## Behavior change

This is not a changelog bullet. If you already consume or will consume `Update` on a hierarchical API, read this first.

- The Wizard no longer ignores sublevels. It generates SDTs, Procedures, and the API Object for the header **and** for the levels you select.
- On `Update`, replacing lines of a sublevel requires the boolean marker `<Sublevel>Replace`. Without it (or with `false`), that level's lines are **not** rewritten. With `true`, the generator matches by primary key or, for an autonumbered PK, does `Clear` + `Add`. Omitting the marker or misreading it **deletes or keeps lines without the effect you expected**.
- Changing grandchildren requires replacing the parent level (`<Sublevel>Replace` on the parent). There are no dedicated sublevel endpoints.
- An API generated in the previous Alpha **does not change by itself**. Reopen the Wizard on it to emit the hierarchical contract and write V2 metadata.
- Re-encountering a flat API (V1 metadata) remains valid: the Wizard writes V2 with null `levels`, and the B067 hash of the flat contract stays stable.

The HTTP 422 contract from `0.1.0-alpha.4` (`ErrorResponse.Message` + `Messages[]`) is unchanged.

## You must choose the correct DLL

Download and install only the file that matches your IDE version:

| GitHub Release asset | For | Not for |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15, and later U14+ releases | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

The `-gx18u13` suffix exists to distinguish the public download. Do not rename a DLL to make it look like another line, and do not install both DLLs in the same IDE.

## What is included

- Hierarchical Wizard: shared selector, parent/child dependency, optional `List` counters on direct children, warning above depth 4 (does not block).
- Own SDTs per contract (`sdt<Tx>_API_<Role>_<path>`), including `ListResponse_Item` when a sublevel is present.
- Hierarchical Business Component source for `Get` / `Create` / `Update`, with the `<Sublevel>Replace` marker.
- Metadata `GOAB_API_METADATA_B060_V2` (`levels`, `own` inventory); Sync and Remove use that tree.
- Skip of an empty Create SDT (child with inherited PK only), so GeneXus does not reject an SDT with no items.

## Validation

- Multilevel HTTP smoke on `.NET`/PostgreSQL and `.NET Framework`/SQL Server (`apiTeste`, four levels): POST/GET, PUT with and without `Replace`, List with counters.
- Hierarchical YAML reviewed; `typescript-fetch` and `csharp` clients generated with `openapi-generator-cli` 5.3.1.
- IDE lifecycle: re-encounter, Sync (including a new attribute on a sublevel), and Remove.
- Criterion 10 on GeneXus 18 U13: Wizard re-encounter and `Build All` on both environments, no `spc0018`. HTTP on U13 was out of this gate (already covered on U15). The 2026-08-29 smoke used the satellite DLL labeled `0.1.0-alpha.4` on Transaction `Teste`. The empty Create SDT skip landed afterwards; on `Teste` that does not change the hierarchical contract, so criterion 10 evidence still holds.
- Criterion 11 on Transaction `Empresa` (13 sublevels): apply, `Build All` Success on both environments, Remove with no orphans.

## Installation

Follow the [public installation guide](../Public/INSTALL.md). In brief:

1. choose the DLL using the table above;
2. with the GeneXus IDE open, use **Extensions Manager → Add > Local**;
3. close the IDE completely;
4. run `genexus /install` in the corresponding installation;
5. reopen the IDE and verify the Genexus Open API Builder menus.

The GitHub Packages `.nupkg` is not the IDE installer. For public installation, use the Release DLL asset.

## Known limitations

- No dedicated sublevel endpoints; `List` counters only on direct children.
- Depth above 4 warns and does not block. `Empresa` with 13 sublevels passed `Build All`; apply at that scale took about 107 minutes on the IDE UI thread, and Remove about 32 seconds with no visible dialog. Do not kill GeneXus mid-run.
- A sublevel PK whose **every** part is a foreign key may still emit `count(<header>)` in List.
- The `DELETE` service is not in this cut (`B100` / `0.1.0-alpha.6`).
- GeneXus native OpenAPI YAML retains the limitations documented in [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md).
- On IIS + .NET Framework, the `PUT` verb requires the handler adjustment described in the [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- Installation without elevation and updates performed only through Add > Local over an already installed DLL remain unproven.
- This is still an Alpha, not a Beta.
