# Release 0.1.0-alpha.5

**Fecha:** 2026-08-30

**Frente:** Sprint 9 — Transactions con subniveles (Fases 0–7)

**Tag:** `v0.1.0-alpha.5`
**Release:** [Alpha en GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.5)

**Idiomas:** [Português do Brasil](0.1.0-alpha.5.md) · [Español](0.1.0-alpha.5.es.md) · [English](0.1.0-alpha.5.en.md)

Esta versión genera encabezado y líneas seleccionadas de Transactions con subniveles, con metadata V2, Sync y Eliminar cubriendo la jerarquía.

## Cambio de comportamiento

No es un ítem de la lista de mejoras: quien ya consume o va a consumir `Update` en una API jerárquica necesita saber esto.

- El Wizard deja de ignorar subniveles. Genera SDTs, Procedures y API Object para el encabezado **y** para los niveles que marque.
- En `Update`, reemplazar líneas de un subnivel exige el marcador booleano `<Subnivel>Replace`. Sin él (o con `false`), las líneas de ese nivel **no** se reescriben. Con `true`, el generador empareja por clave primaria o, en PK autonumerada, hace `Clear` + `Add`. Omitir el marcador o interpretarlo mal **borra o conserva líneas sin el efecto que esperaba**.
- Alterar nietos exige reemplazar el nivel padre (`<Subnivel>Replace` en el padre). No hay endpoints propios de subnivel.
- Una API ya generada en la Alpha anterior **no cambia sola**. Reabra el Wizard sobre ella para emitir el contrato jerárquico y grabar metadata V2.
- El reencuentro de una API plana (metadata V1) sigue siendo válido: el Wizard graba V2 con `levels` nulo y el hash B067 del contrato plano permanece estable.

El contrato HTTP 422 de `0.1.0-alpha.4` (`ErrorResponse.Message` + `Messages[]`) se mantiene.

## Elija obligatoriamente la DLL correcta

Descargue e instale solamente el archivo correspondiente a la versión de su IDE:

| Asset en GitHub Release | Sirve para | No sirve para |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15 y posteriores U14+ | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

El sufijo `-gx18u13` existe para distinguir la descarga pública. No cambie el nombre de una DLL para hacerla pasar por otra línea y no instale las dos en el mismo IDE.

## Qué incluye

- Wizard jerárquico: selector compartido, dependencia padre/hijo, contador de `List` desactivable en hijos directos, aviso de profundidad mayor que 4 (no bloquea).
- SDTs propios por contrato (`sdt<Tx>_API_<Papel>_<camino>`), incluido `ListResponse_Item` cuando hay subnivel.
- Source Business Component jerárquico en `Get` / `Create` / `Update`, con el marcador `<Subnivel>Replace`.
- Metadata `GOAB_API_METADATA_B060_V2` (`levels`, inventario `own`); Sync y Eliminar usan ese árbol.
- Omite SDT Create vacío (hijo solo con PK heredada), para que GeneXus no rechace un SDT sin ítems.

## Validaciones

- Smoke HTTP multinivel en los environments `.NET`/PostgreSQL y `.NET Framework`/SQL Server (`apiTeste`, cuatro niveles): POST/GET, PUT con y sin `Replace`, List con contadores.
- YAML jerárquico comprobado; clientes `typescript-fetch` y `csharp` generados con `openapi-generator-cli` 5.3.1.
- Ciclo de vida en la IDE: reencuentro, Sync (incluido atributo nuevo en subnivel) y Eliminar.
- Criterio 10 en GeneXus 18 U13: Wizard en reencuentro y `Build All` en los dos environments, sin `spc0018`. HTTP en U13 quedó fuera de este gate (ya cubierto en U15). El smoke del 2026-08-29 usó la DLL satélite `0.1.0-alpha.4`; este corte no cambió el generador, así que la evidencia se hereda.
- Criterio 11 en la Transaction `Empresa` (13 subniveles): apply, `Build All` Success en los dos environments, Eliminar sin huérfanos.

## Instalación

Siga la [guía pública de instalación](../Public/INSTALL.md). En resumen:

1. elija la DLL según la tabla anterior;
2. con la IDE GeneXus abierta, use **Extensions Manager → Add > Local**;
3. cierre completamente la IDE;
4. ejecute `genexus /install` en la instalación correspondiente;
5. vuelva a abrir la IDE y confirme los menús de Genexus Open API Builder.

El `.nupkg` de GitHub Packages no es el instalador de la IDE. Para la instalación pública, use el asset DLL del Release.

## Limitaciones conocidas

- Sin endpoints propios de subnivel; contadores de `List` solo en hijos directos.
- Profundidad mayor que 4 avisa y no bloquea. `Empresa` con 13 subniveles pasó el `Build All`; el apply a esa escala tardó unos 107 minutos en el hilo de UI de la IDE, y Eliminar unos 32 segundos sin diálogo visible. No cierre GeneXus a mitad de proceso.
- Una PK de subnivel en la que **todas** las partes son clave foránea todavía puede emitir `count(<encabezado>)` en List.
- El servicio `DELETE` no forma parte de este corte (`B100` / `0.1.0-alpha.6`).
- El YAML OpenAPI nativo de GeneXus mantiene las limitaciones documentadas en [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md).
- En IIS + .NET Framework, el verbo `PUT` requiere el ajuste del handler descrito en el [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- La instalación sin elevación y la actualización solamente por Add > Local sobre una DLL ya instalada continúan sin comprobación.
- Esta versión sigue siendo Alpha, no Beta.
