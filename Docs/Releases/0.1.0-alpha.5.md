# Release 0.1.0-alpha.5

**Data:** 2026-08-30

**Frente:** Sprint 9 — Transactions com subníveis (Fases 0–7)

**Tag:** `v0.1.0-alpha.5`
**Release:** [Alpha no GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.5)

**Idiomas:** [Português do Brasil](0.1.0-alpha.5.md) · [Español](0.1.0-alpha.5.es.md) · [English](0.1.0-alpha.5.en.md)

Esta versão passa a gerar cabeçalho e linhas selecionadas de Transactions com subníveis, com metadata V2, Sync e Remover cobrindo a hierarquia.

## Mudança de comportamento

Não é um item da lista de melhorias: quem já consome ou vai consumir `Update` em API hierárquica precisa saber disto.

- O Wizard deixa de ignorar subníveis. Gera SDTs, Procedures e API Object para o cabeçalho **e** para os níveis que você marcar.
- No `Update`, a substituição de linhas de um subnível exige o marcador booleano `<Subnível>Replace`. Sem ele (ou com `false`), as linhas daquele nível **não** são reescritas pelo gerador. Com `true`, o gerador casa por chave primária ou, em PK autonumerada, faz `Clear` + `Add`. Omitir o marcador ou entendê-lo errado **apaga ou preserva linhas sem o efeito que você esperava**.
- Alterar netos exige substituir o nível pai (`<Subnível>Replace` no pai). Não há endpoints próprios de subnível.
- API já gerada na Alpha anterior **não muda sozinha**. Reabra o Wizard sobre ela para emitir o contrato hierárquico e gravar metadata V2.
- Reencontro de API plana (metadata V1) continua válido: o Wizard grava V2 com `levels` nulo e o hash B067 do contrato plano permanece estável.

O contrato HTTP 422 de `0.1.0-alpha.4` (`ErrorResponse.Message` + `Messages[]`) permanece.

## Escolha obrigatória da DLL

Baixe e instale somente o arquivo correspondente à versão da sua IDE:

| Asset no GitHub Release | Serve para | Não serve para |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15 e posteriores U14+ | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

O sufixo `-gx18u13` existe para distinguir o download público. Não renomeie uma DLL para fazê-la passar por outra linha e não instale as duas na mesma IDE.

## O que entra

- Wizard hierárquico: seletor compartilhado, dependência pai/filho, contador de `List` desligável nos filhos diretos, aviso de profundidade acima de 4 (não bloqueia).
- SDTs próprios por contrato (`sdt<Tx>_API_<Papel>_<caminho>`), inclusive `ListResponse_Item` quando há subnível.
- Source Business Component hierárquico em `Get` / `Create` / `Update`, com o marcador `<Subnível>Replace`.
- Metadata `GOAB_API_METADATA_B060_V2` (`levels`, inventário `own`); Sync e Remover usam essa árvore.
- Skip de SDT Create vazio (filho só com PK herdada), para o GeneXus não recusar SDT sem itens.

## Validações

- Smoke HTTP multinível nos environments `.NET`/PostgreSQL e `.NET Framework`/SQL Server (`apiTeste`, quatro níveis): POST/GET, PUT com e sem `Replace`, List com contadores.
- YAML hierárquico conferido; clientes `typescript-fetch` e `csharp` gerados com `openapi-generator-cli` 5.3.1.
- Ciclo de vida na IDE: reencontro, Sync (incluindo atributo novo em subnível) e Remover.
- Critério 10 no GeneXus 18 U13: Wizard em reencontro e `Build All` nos dois environments, sem `spc0018`. HTTP no U13 ficou fora deste gate (já coberto no U15). O smoke de 2026-08-29 usou a DLL satélite rotulada `0.1.0-alpha.4` na Transaction `Teste`. O skip de SDT Create vazio entrou depois; na `Teste` isso não muda o contrato hierárquico, então a evidência do critério 10 permanece.
- Critério 11 na Transaction `Empresa` (13 subníveis): apply, `Build All` Success nos dois environments, Remover sem órfão.

## Instalação

Siga o [guia público de instalação](../Public/INSTALL.md). Em resumo:

1. escolha a DLL pela tabela acima;
2. na IDE GeneXus aberta, use **Extensions Manager → Add > Local**;
3. feche completamente a IDE;
4. execute `genexus /install` na instalação correspondente;
5. reabra a IDE e confira os menus do Genexus Open API Builder.

O `.nupkg` do GitHub Packages não é o instalador da IDE. Para a instalação pública, use o asset DLL do Release.

## Limitações conhecidas

- Sem endpoints próprios de subnível; contadores de `List` só nos filhos diretos.
- Profundidade acima de 4 gera aviso e não bloqueia. A `Empresa` com 13 subníveis passou no `Build All`; o apply nessa escala demorou cerca de 107 minutos no thread da UI da IDE, e o Remover cerca de 32 segundos sem diálogo visível. Não feche o GeneXus no meio.
- PK de subnível em que **todas** as partes são chave estrangeira ainda pode emitir `count(<cabeçalho>)` no List.
- Serviço `DELETE` não faz parte deste corte (`B100` / `0.1.0-alpha.6`).
- O YAML OpenAPI nativo do GeneXus mantém as limitações documentadas em [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md).
- Em IIS + .NET Framework, o verbo `PUT` exige o ajuste do handler descrito no [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- Instalação sem elevação alguma e atualização somente por Add > Local sobre DLL já instalada continuam sem comprovação.
- A Alpha ainda não é a Beta.
