This release adds the REST `Delete` service as an explicit Wizard option, off by default.

## Behavior change

This is not a changelog bullet. If you already generate or consume APIs from this extension, read this first.

- `Delete` **does not appear by itself** on an already generated API. Reopen the Wizard, check the box, and finish Apply with Complete REST via Business Component.
- Enabling `Delete` requires Complete REST via Business Component in the same Apply. Without that step there is no `proc*_API_Delete` and no route on the API Object.
- KB preferences refuse to save `Delete` alone without `Get`, `Create`, and `Update`.
- `Delete` has its own `SecurityLevel` (combo). On re-encounter, the Wizard radio applies to `List`/`Get`/`Create`/`Update`; Sync preserves the Delete level.
- Deleting the header deletes child lines in the same Business Component transaction. A `404` on a missing id is **not** idempotent (`200`).
- On referential-integrity refusal, `Delete` responds with **HTTP 422** using the same error SDT as `Create`/`Update` (`validation_error`, `Message`, `Messages[]` when message passthrough is on).

Sublevel support from `0.1.0-alpha.5` and the HTTP 422 contract from `0.1.0-alpha.4` remain.

## What is included

- Opt-in REST `Delete` service: Procedure `proc*_API_Delete`, `DELETE` on the Get key path, status `200` / `404` / `422` via Business Component.
- Confirmation when checking the box; own `SecurityLevel`; dependency on Complete REST via Business Component.
- Re-encounter and Sync aligned to the Delete's own level.
- Public docs (README ×3, `DEMO`, Foundation contracts) aligned to the opt-in contract.

## Validation

- HTTP on `apiNotaFiscal`: `401` without token, `404` on missing, `200` on delete across `.NET`/PostgreSQL and `.NET Framework`/SQL Server; integrity `422` on Framework.
- Own level on IIS: `Delete` as `SecurityHigh` and the others as `SecurityLow`; a user without Delete permission gets `403` `code` 139; a permitted user gets coherent `201`/`200`/`404`.
- U15 smoke for re-encounter, Sync, BC dependency, Output `B050-B053/B100`, preview, and preferences.
- U14+ (canonical) and U13 (satellite) Release builds for this cut.

## Installation

Follow the [public installation guide](../Public/INSTALL.md). In brief:

1. choose the DLL using the table above;
2. with the GeneXus IDE open, use **Extensions Manager → Add > Local**;
3. close the IDE completely;
4. run `genexus /install` in the corresponding installation;
5. reopen the IDE and verify the Genexus Open API Builder menus.

The GitHub Packages `.nupkg` is not the IDE installer. For public installation, use the Release DLL asset.

## Known limitations

- `Delete` remains opt-in and off by default; an earlier API only gains the endpoint when you reopen the Wizard with the checkbox marked.
- KB preferences may still re-check generation boxes on re-encounter (`B108`, pending; out of this cut).
- Sublevel limitations from `0.1.0-alpha.5` remain (no dedicated sublevel endpoints; counters only on direct children; depth above 4 warns).
- GeneXus native OpenAPI YAML retains the limitations documented in [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md).
- On IIS + .NET Framework, the `PUT` and `DELETE` verbs require the handler adjustment described in the [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- Installation without elevation and updates performed only through Add > Local over an already installed DLL remain unproven.
- This is still an Alpha, not a Beta.
