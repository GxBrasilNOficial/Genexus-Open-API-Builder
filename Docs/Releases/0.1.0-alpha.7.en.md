# Release 0.1.0-alpha.7

**Date:** 2026-09-01

**Workstream:** Sprint 9 — visual progress feedback, cooperative cancellation, and KB object indexing (`B082`)

**Tag:** `v0.1.0-alpha.7`
**Release:** [Alpha on GitHub](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/releases/tag/v0.1.0-alpha.7)

**Languages:** [Português do Brasil](0.1.0-alpha.7.md) · [Español](0.1.0-alpha.7.es.md) · [English](0.1.0-alpha.7.en.md)

This release introduces real-time visual progress feedback, cooperative cancellation, and KB indexing optimizations, improving the user experience during long operations in the GeneXus IDE.

## What changes for the user

- **Continuous feedback:** The IDE no longer stays silent or appears frozen during Wizard opening, preflight checks, object generation (Apply), synchronization preview (`Sincronizar com a Transaction`), and removal preview (`Remover API gerada`).
- **Abort button:** You can safely cancel an ongoing operation before the first `Save()` without corrupting the KB or leaving orphaned objects.
- **Faster performance:** In-memory indexing avoids repeated KB lookups, speeding up preflight and generation on large KBs and multilevel Transactions.
- **Localization:** Progress screen labels dynamically adapt to the active GeneXus IDE language (Portuguese, Spanish, or English).

Sublevel support (`0.1.0-alpha.5`), the opt-in `Delete` service (`0.1.0-alpha.6`), and the HTTP 422 error contract (`0.1.0-alpha.4`) remain unchanged.

## You must choose the correct DLL

Download and install only the file that matches your IDE version:

| GitHub Release asset | For | Not for |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15, and later U14+ releases | GeneXus 18 Upgrade 13 |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 | GeneXus 18 U14+ |

The `-gx18u13` suffix exists to distinguish the public download. Do not rename a DLL to make it look like another line, and do not install both DLLs in the same IDE.

## What is included

- Modal progress dialog (`ExtensionBusyProgressDialog`) covering Wizard opening, preflight, Apply, Sync preview, and Remove preview.
- Cooperative cancellation mechanism via `ApiPlanBusyProgress`.
- In-memory KB object name and type indexer (`ApiPlanKbObjectNameIndex`).
- Shared folder index refresh (`RefreshFolders`) to avoid redundant `GxOpenAPI` creation attempts.
- Clean phase timing logs in the GeneXus IDE Output window (`[B082]`).

## Validation

- Tested on a complex 13-sublevel Transaction (`Empresa` in `Gx_FabricaBrasil` KB): Apply completed successfully with continuous feedback (~4.2 min), Sync Preview in ~5 s, and Remove Preview in ~2.5 s.
- First Apply tested with shared folder creation (`Company` in `ShowcaseUnanimo` KB): 16 objects created cleanly.
- Cancellation verified before writing with zero side effects on the KB.
- Release builds validated for both canonical U14+ and satellite U13 lines.

## Installation

Follow the [public installation guide](../Public/INSTALL.md). In brief:

1. choose the DLL using the table above;
2. with the GeneXus IDE open, use **Extensions Manager → Add > Local**;
3. close the IDE completely;
4. run `genexus /install` in the corresponding installation;
5. reopen the IDE and verify the Genexus Open API Builder menus.

The GitHub Packages `.nupkg` is not the IDE installer. For public installation, use the Release DLL asset.

## Known limitations

- `Delete` remains opt-in and off by default; an earlier API only gains the endpoint when you reopen the Wizard with the checkbox marked.
- On API removal (`Remover API gerada`), the progress dialog covers the preview and confirmation phase; the actual object deletion after clicking Yes continues with detailed logging in the Output window.
- KB preferences may still re-check generation boxes on re-encounter (`B108`, pending; out of this cut).
- Sublevel limitations from `0.1.0-alpha.5` remain (no dedicated sublevel endpoints; counters only on direct children; depth above 4 warns).
- GeneXus native OpenAPI YAML retains the limitations documented in [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md).
- On IIS + .NET Framework, the `PUT` and `DELETE` verbs require the handler adjustment described in the [README](../../README.en.md#environment-requirement-put-delete-and-patch-on-iis).
- Installation without elevation and updates performed only through Add > Local over an already installed DLL remain unproven.
- This is still an Alpha, not a Beta.
