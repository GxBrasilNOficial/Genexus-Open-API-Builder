# Português (Brasil)

## Atenção — mudança no contrato HTTP do List

Se você já gera APIs com esta extensão e consome o endpoint **List**, leia isto antes de atualizar.

A partir de `0.1.0-alpha.9`, o corpo do `List` deixa de usar o envelope `ListResponse`. Os campos passam a sair **na raiz** do JSON: `Items`, `Pagination`, `AppliedFilters`, `ErrorResponse` (no erro de validação, o mesmo desenho com `ErrorResponse` preenchido).

**Vale para todas as APIs regeneradas com esta versão, qualquer gerador do environment** (incluindo Java e outros além dos .NET). **Breaking:** quem lia `body.ListResponse…` precisa ajustar o cliente e reaplicar o Wizard/Sync.

### Por que mudamos

No GeneXus 18 (U15), o wrapper REST do gerador **.NET** “desembrulha” o SDT de saída quando há **coleção** (caso típico do `List` com `Items`): o JSON efetivo deixa de bater com o Framework e o `ErrorResponse` some de forma inconsistente. O defeito motivador foi medido **só** nesse gerador; mesmo assim unificamos o contrato flat na extensão para **todos** os geradores. Contornos que preservariam `ListResponse` com coleção de itens **falharam**.

Smoke HTTP desta Alpha: .NET Framework/SQL Server e .NET/PostgreSQL. Em Java e demais geradores o contrato gerado é o mesmo — confira um `GET` de List após reaplicar.

Nuance: no .NET Core, `AppliedFilters`/coleções vazias podem ser omitidos do JSON; trate ausência como vazio.

Notas detalhadas: [Português-BR](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/blob/v0.1.0-alpha.9/Docs/Releases/0.1.0-alpha.9.md).

Na IDE GeneXus, abra **Extensions > Manage Extensions**, use **Add > Local** e selecione a DLL correspondente à sua versão. Feche completamente a IDE e execute `genexus /install`. Reabra, confira os menus e **reaplique o List** nas APIs existentes.

# English

## Attention — List HTTP contract change

If you already generate APIs with this extension and consume the **List** endpoint, read this before upgrading.

Starting with `0.1.0-alpha.9`, the `List` body no longer uses the `ListResponse` envelope. Fields are returned at the **root** of the JSON: `Items`, `Pagination`, `AppliedFilters`, `ErrorResponse` (on validation errors, the same shape with `ErrorResponse` populated).

**This applies to every API regenerated with this version, whatever generator the environment uses** (including Java and others beyond .NET). **Breaking:** callers that read `body.ListResponse…` must update the client and re-run Wizard/Sync.

### Why we changed it

On GeneXus 18 (U15), the **.NET** REST wrapper unwraps the output SDT when it contains a **collection** (typical `List` with `Items`): the effective JSON stops matching Framework, and `ErrorResponse` disappears inconsistently. The motivating defect was measured **only** on that generator; we still unified the flat contract in the extension for **all** generators. Workarounds that would keep `ListResponse` with an items collection **failed**.

HTTP smoke in this Alpha: .NET Framework/SQL Server and .NET/PostgreSQL. On Java and other generators the generated contract is the same — verify a List `GET` after reapplying.

Nuance: on .NET Core, empty `AppliedFilters`/collections may be omitted from JSON; treat absence as empty.

Detailed notes: [English](https://github.com/GxBrasilNOficial/Genexus-Open-API-Builder/blob/v0.1.0-alpha.9/Docs/Releases/0.1.0-alpha.9.en.md).
