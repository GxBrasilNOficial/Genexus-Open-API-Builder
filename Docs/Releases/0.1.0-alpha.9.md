## Atenção — mudança no contrato HTTP do List

Se você já gera APIs com esta extensão e consome o endpoint **List**, leia isto antes de atualizar.

A partir de `0.1.0-alpha.9`, o corpo do `List` deixa de usar o envelope `ListResponse`. Os campos passam a sair **na raiz** do JSON:

| Situação | Corpo |
| --- | --- |
| Sucesso | `Items`, `Pagination`, `AppliedFilters`, `ErrorResponse` |
| Erro de validação (ex.: `pageSize` inválido) | o mesmo desenho, com `ErrorResponse` preenchido |

**Isso vale para todas as APIs regeneradas com esta versão, qualquer que seja o gerador do environment** (incluindo Java e outros além dos .NET). Não há ramo “só .NET” vs “Framework antigo”: a extensão passa a emitir o mesmo contrato flat em todos.

**Breaking change.** Quem lia `body.ListResponse.Items` (ou equivalente) precisa ajustar o cliente e reaplicar o Wizard (ou Sincronizar) sobre cada API gerada.

### Por que mudamos (não foi preferência de desenho)

No GeneXus 18 (medido no U15), o **wrapper REST gerado pelo .NET** trata de forma especial um `out` cujo SDT contém **coleção** — o caso típico do `List`, com `Items`:

- no sucesso, ele “desembrulha” o SDT e devolve só o conteúdo interno;
- o `ErrorResponse` deixa de aparecer de forma consistente no HTTP;
- o YAML ainda anunciava `ListResponse` + `ErrorResponse`, mas o JSON real no .NET **não** batia com o do .NET Framework.

O defeito motivador foi medido **só** nesse gerador .NET. No Framework o envelope antigo com `ListResponse` era estável. Mesmo assim unificamos o contrato na extensão: um único Shape para BFF/clientes, alinhado ao YAML, e sem depender do comportamento assimétrico de um gerador.

Testamos contornos que preservariam `ListResponse` (incluindo um terceiro `out` e variações do SDT). **Com coleção de itens — o desenho que o List precisa — o desembrulho volta.** O caminho estável que validamos foi abandonar `ListResponse` no contrato público e expor os outs flat. No reapply, a extensão remove o SDT `*ListResponse` órfão quando era de posse dela.

Sem isso, BFF/front fora do GeneXus não conseguem um contrato único entre environments.

### O que validamos nesta Alpha

Smoke HTTP e paridade de corpo em:

- .NET Framework / SQL Server
- .NET / PostgreSQL

Em **Java e demais geradores**, o contrato **gerado** é o mesmo; a equivalência runtime **não** foi exercida por nós nesta release — quem publica nesses environments deve conferir um `GET` de List após reaplicar o Wizard.

Nuance: no .NET Core, `AppliedFilters` vazio ou coleções vazias podem ser omitidos do JSON; trate ausência como “vazio”, não como erro de contrato.

### O que fazer ao atualizar

1. Instale a DLL desta release (escolha U14+ ou U13− abaixo).
2. Na KB, reabra o **Wizard** (ou **Sincronizar**) sobre cada API gerada e aplique de novo o `List`.
3. Atualize clientes/geradores OpenAPI que ainda navegam por `ListResponse`.
4. Faça `Build All` nos environments que publica e confira um `GET` de List — em especial se usar Java ou outro gerador além dos dois .NET acima.

Detalhe técnico e evidência: [plano B120](../Implementation/2026-09-10-B120-ENVELOPE-HTTP-LIST-MULTIPLATAFORMA.md) e [aceite IDE/HTTP](../Implementation/2026-09-24-B120-ACEITE-IDE-SMOKE-HTTP.md).

## Escolha obrigatória da DLL

Baixe e instale somente o arquivo correspondente à versão da sua IDE:

| Asset no GitHub Release | Serve para | Não serve para |
|---|---|---|
| `GenexusOpenApiBuilder.Extension.dll` | GeneXus 18 Upgrade 14, Upgrade 15 e posteriores (**U14+**) | GeneXus 18 **U13−** (Upgrade 13 e anteriores) |
| `GenexusOpenApiBuilder.Extension-gx18u13.dll` | GeneXus 18 Upgrade 13 e anteriores (**U13−**) | GeneXus 18 **U14+** |

O sufixo `-gx18u13` existe para distinguir o download público. Não renomeie uma DLL para fazê-la passar por outra linha e não instale as duas na mesma IDE. A linha **U13−** foi validada formalmente no Upgrade 13; upgrades anteriores podem funcionar, sem matriz de teste completa nesta Alpha.

## Instalação

Siga o [guia público de instalação](../Public/INSTALL.md). Em resumo:

1. escolha a DLL pela tabela acima;
2. na IDE GeneXus aberta, use **Extensions Manager → Add > Local**;
3. feche completamente a IDE;
4. execute `genexus /install` na instalação correspondente;
5. reabra a IDE, confira os menus e **reaplique o List** nas APIs existentes.

O `.nupkg` do GitHub Packages não é o instalador da IDE. Para a instalação pública, use o asset DLL do Release.

## Limitações conhecidas

- Contrato flat do List: validação HTTP desta Alpha nos dois .NET; Java e demais geradores geram o mesmo contrato sem matriz runtime nossa nesta release.
- Preferências da KB ainda podem religar checkboxes de geração no reencontro (`B108`, estacionado).
- Família de falhas intermitentes de Apply em KB muito grande sob investigação (`B109`, inclusive ramo C).
- Continuação de Apply/Sync interrompido fora de escopo; use Recuperar para encerrar o registro e depois Wizard ou Remover.
- Limitações de subníveis de `0.1.0-alpha.5` permanecem.
- O YAML OpenAPI nativo do GeneXus mantém as limitações documentadas em [B088](../Implementation/2026-08-10-B088-LIMITACOES-YAML-NATIVO.md).
- Em IIS + .NET Framework, os verbos `PUT` e `DELETE` exigem o ajuste do handler descrito no [README](../../README.md#requisito-de-ambiente-put-delete-e-patch-em-iis).
- A Alpha ainda não é a Beta.
